## Что делалось?

1. Сформулирована задача локализации и классификации дефектов металла. Для сравнения нужны модели детекции, разметка рамками, единый test и одинаковый расчёт показателей.
2. Рассмотрены источники данных и литература. Выбран c5data2: задача соответствует предметной области, есть пять классов и XML-разметка рамками. MVTec изучался как иной подход к промышленным дефектам; основной эксперимент проведён на c5data2.
3. На первоначальном этапе в переписке с DeepSeek подготовлены преобразование Pascal VOC XML в YOLO, разбиение train/val/test, команды обучения и ноутбук для Colab. Это часть разработки; итоговые показатели получены из реальных запусков.
4. Установлены соответствия папок и class ID 0–4. Координаты нормализованы по реальным размерам изображений. После shuffle с seed 42 получены 752 / 161 / 162 изображения.
5. Проведена проверка данных: 1075 изображений, 1444 объекта, выраженный дисбаланс, размеры преимущественно 2048×1000. Точные файловые и пиксельные дубликаты не найдены; близкие дубликаты отдельно не проверялись.
6. На Windows / RTX 3050 обучены YOLOv8n, YOLOv8s и YOLOv8n с усиленной аугментацией, по 50 эпох. У базовых YOLO тоже есть штатные аугментации; дополнительный вариант изменял mixup и поворот.
7. В Google Colab обучены Faster R-CNN и SSD, по 10 эпох. Faster R-CNN инициализирован COCO V1, SSD и backbone обучались с нуля. В архиве сохранены фактические настройки; новые локальные defaults не выдаются за исходные настройки Colab.
8. При проверке раннего DETR обнаружена неправильная нормализация рамок через фиксированный размер 512. Этот результат исключён из итогового сравнения. Исправлены подготовка target, processor, размеры изображения и преобразование форматов рамок; DETR обучен заново, лучший checkpoint выбран на val.
9. Для пятого семейства добавлен EfficientDet-D0: проверено предобучение COCO, заменена голова на пять классов, реализованы преобразования XYXY → YXYX и ID 0–4 → 1–5. После пробного backward выполнено обучение 10 эпох.
10. Исправлены практические проблемы: запуск процессов Windows через защиту __main__ и freeze_support, настройка workers, ограничение выходных рамок EfficientDet границами изображения, удаление рамок нулевой площади, сохранение checkpoint до оценки. Исправлена одна исходная обучающая рамка с ymin=-1; test сохранён.
11. Собран общий pipeline из модулей и конфигураций с точкой входа main.py. Проверяются контрольные суммы весов и датасета, фиксируются параметры runtime, ошибки каждого эксперимента и отдельная папка результатов.
12. На общей тестовой выборке из 162 изображений / 226 объектов рассчитаны AP101, mAP50, mAP50–95 и micro Precision / Recall / F1. Confidence для P/R/F1 равен 0.25, IoU — 0.50. Test не использовался для обучения и выбора checkpoint.
13. Для SSD проверено, что изменение режима cuDNN влияет на численные предсказания тех же весов. Старый и текущий режимы воспроизведены; актуальная таблица использует единый явно зафиксированный протокол, выбранный независимо от лучшего test-результата.
14. Для EfficientDet исследованы минимальные расхождения координат при повторном запуске: до 0.000030517578 пикселя, при неизменных классах, confidence и числе обнаружений. Итоговые метрики совпали. Последняя проверка сохранённых экспортов не запускала переобучение.
15. Сформированы таблицы, графики обучения, показатели по классам, PR-кривая, матрица ошибок и примеры обнаружений. Подготовлены Word-отчёт и презентация по присланным образцам.
16. Для публикации выделены исходники и проверенные результаты в Git-репозиторий. Датасет и точные обученные веса собираются в архивы Releases с сохранением путей и контрольных сумм.

## Что получилось?

YOLOv8s показал лучший mAP50 и F1, YOLOv8n — лучший mAP50–95, Faster R-CNN — лучший Recall при большом количестве ложных обнаружений.
Слабые результаты SSD и DETR сохранены в сравнении и обсуждаются вместе с условиями обучения.
Длительность, предобучение, размеры входа и выбор checkpoint различались; проведён один исторический запуск каждого варианта. Эти ограничения не позволяют объявить архитектуру лучшей вообще.

Исходные конфигурации и проверки: `configs/experiment_provenance.json`, `configs/runtime_protocol.json`, `results/reference/ssd/runtime_validation.json`.
Численные результаты: `results/final/`, `comparison_table.csv`. Полное описание и литература — в Word-отчёте.
